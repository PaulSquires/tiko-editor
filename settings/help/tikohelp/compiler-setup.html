Compiler setup

Tiko ships with a FreeBASIC toolchain ready to use. How toolchains are organised, how to add more, and how the 32- and 64-bit choice is really made.

ImportantTiko already comes with a compiler. The most recent FreeBASIC toolchain ships with the editor and is installed and selected out of the box, so there is normally nothing to set up — you can build and run from the moment you unpack it.

You only need this page if you want to add a toolchain — an older FreeBASIC version to check compatibility against, a newer one to try, or a variant built with a different backend — and switch between them.

How toolchains are organised

Compiler toolchains live as subfolders of the toolchains\ folder, beside tiko.exe. Each subfolder is one complete toolchain, and you may install as many as you like.

textThe toolchains folder
tiko.exe
toolchains\
    FreeBASIC-1.10.1-winlibs-gcc-9.3.0\     <- ships with Tiko
        fbc32.exe                            <- both executables are required
        fbc64.exe
        bin\  inc\  lib\  examples\  doc\
    FreeBASIC-1.09.0\                        <- add as many as you like
        fbc32.exe
        fbc64.exe
        ...
ImportantEach toolchain must have both fbc32.exe and fbc64.exe in its root folder. Tiko always resolves both from the one folder you select, because the 32-bit or 64-bit choice is made per build, not per toolchain — see below.

Adding a toolchain

  1. Unpack the FreeBASIC distribution into a new subfolder of toolchains\. Name the folder something you will recognise in a list — the version number is the obvious choice.
  2. Check that fbc32.exe and fbc64.exe are both directly in that folder, not one level down.
  3. Open File›Settings›Options… and select the Compiler page.
  4. The new toolchain appears in the list — Tiko scans the folder each time the page opens, so nothing needs registering.

Choosing which toolchain to use

  1. Open File›Settings›Options….
  2. Select the Compiler page.
  3. Click the toolchain you want in the list.
  4. Choose OK.
Note

Selecting a toolchain sets the paths to both its compilers together. You never pick an individual .exe, which is why the two files must both be present.

The rest of the Compiler page

ControlWhat it does
Toolchain listEvery subfolder of toolchains\. The selected one supplies both compilers.
Compiler switchesExtra switches added to every build, whatever the project or build configuration. Normally left empty — switches usually belong in a build configuration or in project options instead.
Include pathsAdditional directories searched for #include files, on top of the toolchain's own inc folder.
Run via command windowLaunch your compiled program through a command window rather than directly. Useful for a console program that exits immediately, so you can still read its output.
Disable compile beepSuppress the sound Tiko makes when a build finishes.

32-bit and 64-bit

ImportantArchitecture is chosen by the build configuration, not by the toolchain. Because every toolchain provides both fbc32.exe and fbc64.exe, switching between a Win32 and a Win64 build is a matter of selecting a different build configuration — Tiko then invokes the matching compiler from the toolchain you selected.

If your project links against a DLL or static library of a particular architecture, the two must match: a 64-bit program cannot load a 32-bit DLL.

Checking that it works

  1. Create a new file and type a one-line program: Print "ok" : Sleep
  2. Save it.
  3. Press F5.
  4. The Output panel should show the compiler being invoked, and your program should run.
Warning

If the build fails immediately with a message about the compiler not being found, the problem is Tiko's configuration rather than your code. Check that a toolchain is selected on the Compiler page, and that the folder it names still contains both fbc32.exe and fbc64.exe. See Troubleshooting.

Compiler switches

Switches reach the compiler from four places, which combine:

  1. The active build configuration — the reusable set, such as debug or release, and the one that decides 32- or 64-bit.
  2. The project's own compiler options — switches specific to this project.
  3. The Compiler switches field on the Compiler options page — applied to every build in every project. Use sparingly.
  4. Anything Tiko must add itself, such as the output file name.
TipCompile›Command Line… shows the exact command line Tiko will use. When a build does something you did not expect, look there first — it usually settles the question immediately.
