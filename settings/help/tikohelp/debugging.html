Debugging

Running your program under Tiko Editor's debugger: starting and stopping, stepping, the four debugger panes, and inspecting values.

Tiko Editor has a real source-level debugger. It runs your program under its own control, so you can stop it at a chosen line, step through it a statement at a time, and look at the value of any variable while it is stopped.

The debugger reads the debug information the FreeBASIC compiler emits directly, so the program you debug is the same binary you built — not a differently-generated one.

Before you start

  1. Select a build configuration that produces debug information — a Debug configuration.
  2. Build the project (Ctrl + F5) so the executable is current.
  3. Set at least one breakpoint, otherwise the program simply runs to completion.

Starting and stopping

CommandShortcutWhat it does
Start DebuggingF6Builds if needed, launches your program under the debugger and runs it until it hits a breakpoint.
Continue DebuggingF6The same command once a session is running: resumes from where it stopped.
BreakCtrl + F6Interrupts a running program at the next line of your source.
Stop DebuggingShift + F6Ends the session and terminates the program.
NoteBreak stops at the next line of your code, so a program sitting inside a long Sleep or blocked in a library call will not stop until it returns to your source. Stop Debugging works at any time.

Stepping

CommandShortcutWhat it does
StepF11Executes the current line. If it calls one of your procedures, stops on that procedure's first line.
Step OverF10Executes the current line, running any call it makes to completion without stopping inside.
Step OutShift + F11Runs until the current procedure returns, then stops at the caller.
Run to CursorCtrl + F10Resumes and stops when execution reaches the line the caret is on — a breakpoint you do not have to set and clear.
Tip

Step Over (F10) is the one to reach for by default. Use Step (F11) only when you actually want to go inside the call — otherwise you spend your time in code you were not investigating.

The line about to execute is marked in the editor, and the marker follows you as you step.

The debugger window

While debugging, four panes show you the state of your program:

PaneShows
GlobalsVariables visible throughout the program.
LocalsVariables in the procedure currently in scope. Click a call stack frame to see that frame's locals instead.
Call stackThe chain of calls that reached the current line, innermost first. Click a frame to look at its scope.
WatchExpressions you asked to track. Click the placeholder row to add one, click a row to edit it, and use the × column to delete it.

Inspecting values

  • Hover the mouse over a variable in the editor to see its value in a data tip.
  • Expand a structure or array with its twisty to see its members or elements.
  • Large arrays are grouped into ranges — a ten-thousand-element array appears as a hundred groups of a hundred rather than ten thousand rows — so you can drill down to one element without scrolling past the rest.
  • Values that changed since the program last stopped are shown in a different colour, which makes stepping through a loop far easier to follow.
Note

Values are read while your program is stopped, so they are always consistent. Expanding a structure or adding a watch does not resume the program.
