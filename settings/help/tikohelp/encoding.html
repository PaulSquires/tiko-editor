Encoding and line endings

Character encodings, UTF-8 and Unicode, byte-order marks, and the three line-ending conventions — how to see and change each.

Every text file is a sequence of bytes, and an encoding is the rule for turning those bytes into characters. Choose the wrong one and accented letters, symbols and non-Latin scripts come out as garbage.

Encodings Tiko works with

Four, and the names below are exactly what the status bar shows:

Shown asEncodingNotes
UTF-8UTF-8, no byte-order markThe modern default. Represents every Unicode character and is byte-compatible with ASCII for plain English text. Use this unless you have a reason not to.
UTF-8 (BOM)UTF-8 with a byte-order markThe same encoding, preceded by a marker identifying it. Some tools require the marker; others choke on it.
UTF-16 (BOM)UTF-16 with a byte-order markTwo bytes per character. Common in Windows APIs, less so in source files. Tiko always writes the byte-order mark for UTF-16 — there is no BOM-less variant.
ANSIThe system code pageThe legacy Windows encoding for your locale. Fine for plain ASCII, unreliable for anything else.

Seeing and changing the encoding

The status bar shows the current document's encoding. Click it to convert the document to a different encoding.

Warning

Converting to a narrower encoding can lose characters permanently. Converting a UTF-8 file containing, say, Greek text to ANSI will destroy that text. Save a copy first if you are unsure.

Two settings govern the defaults:

New file encoding
The encoding given to files you create.
Unicode encoding
How Tiko treats files whose encoding it cannot determine.

Line endings

Text files mark the end of a line in one of three ways:

StyleBytesConvention
CRLF0D 0AWindows. The default for new files.
LF0AUnix, Linux, macOS. Common in cross-platform projects and in Git repositories.
CR0DClassic Mac OS. Rare today.

The status bar shows the current style; click it to convert the whole document. Tiko detects the style when it opens a file and preserves it on save, so opening a Unix-style file and saving it does not silently rewrite every line.

Tip

Mixed line endings in one file cause odd-looking diffs and confuse some compilers. If a file behaves strangely, converting it to a single consistent style is a cheap fix.

Unicode in source code

FreeBASIC source is normally plain ASCII, but string literals and comments may contain anything. If your program handles non-English text, save the source as UTF-8 and be explicit in code about how those strings are encoded at runtime — the file encoding and the runtime encoding are separate questions.
