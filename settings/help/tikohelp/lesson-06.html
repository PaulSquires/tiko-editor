Lesson 6 — Building a program

Configure the compiler, build and run your project, and navigate compiler errors.

Goal: Configure the compiler, build and run your project, and navigate compiler errors.Time: 20 minutesBefore you start: Lesson 5, plus a FreeBASIC compiler.

What you will learn

  • Setting the compiler path.
  • Building and running with one keystroke.
  • Reading build output and jumping to an error.
  • When to use Compile, Run Executable and Quick Run.
Note

This lesson needs a FreeBASIC compiler installed. If you do not have one, skip ahead to Lesson 8 and come back later.

Point Tiko at the compiler

  1. Open File›Settings›Options….
  2. Select the Compiler page.
  3. Browse to your FreeBASIC installation and select the compiler executable.
  4. Choose OK.

This is a one-off. Tiko remembers it for every project.

Build and run

  1. Make inventory.bas the active document.
  2. Press F5.
  3. The Output panel opens on its Compiler tab and shows the build.
  4. Your program runs in a console window. Type nothing — it prints and waits for a key.
  5. Press a key to close it.

That single keystroke saved your files, compiled the project and ran the result.

Break it deliberately

Errors are more instructive than successes, so introduce one:

  1. In inventory.bas, change Describe( qty1 ) to Descrbe( qty1 ).
  2. Press F5.
  3. The build fails, and the Output panel lists the error.
  4. Click the error row. Tiko jumps to the exact line.
  5. Fix the typo and press F5 again. It builds.
Important

Always fix the first error and rebuild. One early mistake commonly produces a cascade of later errors that disappear on their own once it is fixed.

The other build commands

  1. Press Ctrl + F5 — Compile. It builds but does not run.
  2. Press Shift + F5 — Run Executable. It runs the build you just made, without recompiling.
  3. Press Ctrl + Shift + F5 — Quick Run. It compiles and runs the current file on its own, ignoring the project.
Tip

Quick Run makes Tiko a good scratchpad. Open a new file, type ten lines to test a language feature, and press Ctrl + Shift + F5 — no project needed.

See the command line

Choose Compile›Command Line… to see exactly what Tiko passes to the compiler. When a build does something unexpected, this usually explains it in one glance.

Expected result

The program compiles and runs, printing three lines with a description beside each quantity, and you have navigated to a compiler error by clicking it.

Common mistakes

SymptomCause and fix
The build fails saying the compiler was not found.The compiler path is wrong. Go back to File›Settings›Options… and check it — this is a configuration error, not a code error.
The program window flashes and vanishes.Your program ended without waiting. Add Sleep at the end.
Errors point at lines that look fine.Fix the first error and rebuild; the rest often go with it. An unterminated block is reported far below where it was opened.
The build succeeds but runs old behaviour.A file was not saved. Check that Compile autosave is on.

Review

  • F5 builds and runs; Ctrl + F5 builds only.
  • Clicking an error jumps to its line.
  • Quick Run builds the current file alone, ignoring the project.
  • Compile›Command Line… shows exactly what is passed to the compiler.

Practice

  1. Introduce three different errors at once and practise fixing them from the top down.
  2. Remove the #include line and read the error you get.
  3. Use Quick Run on a brand-new scratch file that prints the numbers 1 to 10.

What's next?
