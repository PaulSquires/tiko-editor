Projects and workspaces

Tiko Editor's single workspace model: why every set of open files is already a project, how to name one, and what a project contains.

ImportantIn Tiko Editor, every workspace is a project. There is no "no project open" state. If you simply open a few loose files, those files are a project — an untitled one. Naming it later is a save, not a conversion.

This one rule removes a great deal of the ceremony other editors ask for. You never have to create a project before you can work, and you never lose your work because you forgot to.

Named and untitled workspaces

Untitled workspaceNamed project
Created byJust opening or creating files.Choosing Save as Project… and giving it a name.
Stored insettings\default.tiko, automatically.A .tiko file wherever you put it.
Reopens on start-upYes.Yes.
Appears in Recent ProjectsNo — it has no name.Yes.
Shown in the window captionNo project name.The project name.
Has project optionsYes.Yes.

Because the untitled workspace is saved automatically, the files you had open are always restored the next time you start — whether or not you ever named the project.

Creating a project

Promote the workspace you already have

This is the usual route, and the easiest:

  1. Open the files you want to work on.
  2. Click the pinned Save as Project… row at the top of the Explorer, or choose Project›Save Project As….
  3. Choose a folder and a name. The workspace becomes a named project containing exactly the files you already had.

Start from nothing

Project›New Project… closes the current workspace and starts a fresh untitled one. There is no dialog — you are simply given a clean slate.

Opening a project

  • Project›Open Project… and choose a .tiko file.
  • Project›Recent Projects lists the ten most recent, and ends with Clear this list.
  • Tiko Editor reopens your last workspace automatically when it starts.
Note

Opening a project closes the current workspace first, prompting you to save anything modified. If you cancel that prompt, the open is abandoned and nothing changes.

Saving and closing

CommandWhat it does
Save ProjectWrites the project file — its file list and options.
Save Project As…Writes it under a new name; that becomes the current project. Also how an untitled workspace gets a name.
Close ProjectCloses the workspace and every file in it, then starts a fresh untitled workspace — because there is always a workspace.

Saving the project and saving your files are separate. Ctrl + S saves documents; Save Project saves the list of them. Tiko Editor prompts for unsaved documents when it needs to.

What is in a project

  • The list of files that belong to it, with each file's category.
  • Which file is the main module, and which is the resource script.
  • Project options — compiler switches, build output settings and command-line arguments.
  • Project notes and the collected TODO list.
Note

A .tiko project file is a plain text file. You can put it in version control alongside your source, and diffs of it are readable.

File categories

Every file in a project sits in exactly one of five categories, shown as permanent group headers in the Explorer. All five are always present, whether or not they currently hold anything — an empty category is visible as an empty group, which makes it obvious where a file would go.

CategoryHoldsLimit
MainThe module with your program's entry point — the file the build commands compile.Exactly one file
ResourceThe resource script (.rc).Exactly one file
HeaderYour .bi include files.Any number
ModuleThe rest of your .bas source files.Any number
NormalAnything else you want kept with the project — notes, data files, build scripts.Any number
ImportantMain and Resource hold exactly one file each. That is what makes them meaningful — they name the entry point and the resource script. Setting a new one displaces the old, which moves to Normal rather than being lost.

Tiko Editor assigns a category from the file's extension when you add it. The first .bas file to enter a workspace with no main module becomes the main module; later ones become ordinary modules. To change a file's category afterwards, right-click it in the Explorer or on its tab and pick the type, or drag it to another group — see Adding and removing files.

Note

The category captions are stored in the project, so you can rename them to suit a particular project's vocabulary. The five categories themselves are permanent and cannot be deleted or added to.

Folders inside a category

The three unlimited categories — Header, Module and Normal — can be given folders to organise a project with many files. Main and Resource cannot: a folder holding one file would have nothing useful in it.

ActionHow
Create a folderUse the add icon on a category header, or its context menu.
Rename a folderClick its rename icon, press F2, or use the context menu. The name is edited in place.
Delete a folderUse its delete icon. See the note below about what happens to its contents.
Move files or foldersDrag them within or between categories.
ImportantDeleting a folder dissolves it — it never destroys anything. The files and any sub-folders inside it move up one level to the deleted folder's parent. That is why no confirmation is asked for: nothing can be lost.
Note

These folders are Tiko Editor's own organisation, not folders on disk. A file's folder is remembered per category, so moving a file to a different category clears its folder — a folder under Module is not the same place as a folder under Normal.
