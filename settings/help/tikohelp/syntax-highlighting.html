Syntax highlighting

How Tiko Editor colours code, choosing the language for a file, editing the keyword lists, and the difference between displaying and rewriting keyword case.

Syntax highlighting colours your code according to what each piece of it means — keywords, strings, comments, numbers, types. Tiko Editor highlights through Lexilla, the lexer library that accompanies Scintilla.

Turning it on and off

The Syntax highlighting option controls it globally. It is on by default; turning it off displays everything in one colour, which can be marginally faster on extremely large files.

Choosing the language for a file

Tiko Editor picks a syntax scheme from the file's extension. There is no language selector on the status bar, so a file with an unusual extension is highlighted according to that extension.

Keyword lists

The words highlighted as keywords come from three plain-text files in settings\keywords. Each has its own page in File›Settings›Options…, so you can edit them without leaving the editor.

Options pageFileHolds
FreeBASIC Keywordsfreebasic_keywords.txtThe FreeBASIC language itself — statements, types, operators and the # and $ directives.
Windows API Keywordswinapi_keywords.txtWin32 API function names, from AbortDoc onwards. Several thousand of them.
Extra Keywordsextra_keywords.txtEverything else you want recognised — third-party library and framework names. This is the one to add your own to.

The files are simply whitespace-separated lists of names, so they are easy to edit or generate. A fourth file, freebasic_keywords_default.txt, holds the shipped baseline so the FreeBASIC list can be restored if you edit it into a corner.

Those lists do three jobs at once:

  • they decide what gets highlighted as a keyword;
  • they supply entries to the autocomplete list;
  • they provide the canonical spelling used by the formatter's keyword-case rules and by the editor's proper-case display.
Important

Because the canonical spelling comes from these files, enter each keyword the way you want to see it written — ByVal, ScreenRes, MessageBox — rather than in lower case. Matching itself is not case-sensitive, so the spelling in the file is purely about presentation.

Tip

Adding your library's procedure names to Extra Keywords is one of the highest-value five minutes you can spend in Tiko Editor: those names then colour correctly and appear in autocomplete throughout the project.

Note

A separate file in the same folder, codetips.ini, supplies the parameter hints shown for built-in FreeBASIC keywords — entries such as ABS=Abs(number). Your own procedures get their code tips from the parser instead. See Autocomplete and code tips.

Keyword case display

The Keyword case setting controls how keywords are displayed. It is a display setting only: it never changes a byte in your file.

SettingKeywords appear as
Original caseExactly as you typed them. The default.
Proper caseThe canonical spelling from the keyword lists — so byval displays as ByVal however you typed it.
Upper caseBYVAL
Lower casebyval

Proper case is the interesting one: it lets you type in whatever case you find quickest and still read consistently-cased code, without a single byte of the file changing. That is why the spelling you enter in the keyword lists matters.

Important

This is a different thing from the formatter's Case keywords rule, which rewrites the file. The two can legitimately disagree — you might display keywords in proper case while leaving the file exactly as written.

Colours

Every syntactic element gets its colour from the current theme. To change one, use the theme editor — see The theme editor.
